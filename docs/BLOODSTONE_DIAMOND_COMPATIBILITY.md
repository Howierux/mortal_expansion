# Bloodstone as a diamond substitute

Bloodstone is registered in the NeoForge/common `c:gems/diamond` item tag, the modern ore-dictionary equivalent, as well as `c:gems/bloodstone` and `c:gems`. Recipes from vanilla, Mortal Expansion and other mods that use the shared diamond tag accept it automatically. The vanilla diamond-block recipe is generated with this tag too: nine Bloodstone, diamonds or a mixture produce one Diamond Block.

Bloodstone gear deliberately keeps its existing all-Bloodstone patterns. The nine vanilla diamond tool/armor recipes use a native difference ingredient (`c:gems/diamond` minus Bloodstone) to avoid competing with those patterns, while retaining other mods' diamond equivalents. To make diamond gear instead, craft one Bloodstone into one Diamond (1:1), then use the ordinary diamond recipe. This conversion is explicit and one-way; diamond-block decompression remains vanilla.

Tag compatibility cannot force third-party recipes that explicitly require the diamond item or use custom item checks to accept a different item. The 1:1 conversion provides a route for those recipes as well. The declared NeoForge dependency loads Mortal Expansion afterward so its generated vanilla-namespace gear overrides take precedence over NeoForge defaults. No Ingredient matching mixin, recipe reload mutation, custom serializer or JEI dependency is introduced. Recipes and tags are generated through framework builders, keeping outputs visible in ordinary recipe tools and reload-safe. Existing Bloodstone repair rules, loot, stats and saved items are unchanged. Migration checks should preserve shared tag naming, the native difference ingredient and the protected gear patterns.

Validation checks loaded shared tags, actual enchanting-table/diamond-block/conversion crafting, unique Bloodstone gear results, and diamond-accepting ingredients across the loaded crafting catalog (with the documented nine gear exceptions). Other mods with custom recipe implementations still require their own compatibility testing.
